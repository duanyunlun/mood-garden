## 2. 项目背景与产品定位

### 2.1 项目背景

心理学研究表明，长期坚持"感恩日记"（Gratitude Journal）——即每天记录若干件让自己感到"谢谢，真好呀"的小事——可以显著提升大脑快乐神经元的活跃度，帮助使用者建立更积极的思维模式，缓解焦虑与负面情绪的累积。然而市面上现有的情绪记录类工具，多以"打卡""统计"为核心逻辑，记录体验偏功能化、缺乏情感反馈与仪式感，用户难以获得持续记录的正向激励，留存率普遍不高。

在此背景下，本产品希望构建一款兼具"情绪疗愈"与"轻养成游戏"双重属性的情绪记录 App，让用户在记录情绪的过程中获得即时的、可视化的情感反馈与陪伴感，从而更愿意长期、自发地坚持记录。

### 2.2 产品定位

本产品是一款面向 iOS 平台的情绪记录类 App。产品在"感恩日记"理论基础上，做了两个关键创新：

- 开心的事记录后会产生"奖赏感"——种下一颗花的种子，花会随时间在花园中真实生长；

- 不开心的事记录后可以"烧掉"释放，且烧掉产生的灰烬会转化为花园的养分/肥料，反哺让美好的事物长得更好。

产品的核心心智可以概括为一句话："每一种情绪都有价值，开心的事被温柔地收藏，不开心的事被温柔地转化"。产品期望通过"花园养成"这一具有强情感联结与持续吸引力的机制，成为用户情绪记录习惯的长期陪伴者。

### 2.3 设计风格总览

整体视觉风格要求清新治愈、温暖柔和，色系以奶油白为基底，暖橘黄用于表达开心/花朵元素，雾雾灰粉用于表达不开心/纸卷元素，鼠尾草绿作点缀色。界面构成以圆角卡片和手绘插画风格为主，弱化数据化、工具化的视觉语言，强化情感陪伴感。

## 3. 竞品分析

本产品在机制设计上重点参考了以下两款 iOS 情绪记录类产品，分别吸收其"低门槛输入体验"与"仪式感释放交互"的长处，并在此基础上叠加自身独有的"花园养成"差异化机制。

### 3.1 Clovery 小幸运

- 核心亮点：极低门槛记录，一句话、一张照片、一个标签即可完成一次记录，大幅降低用户的输入负担；

- 多样化视图回顾任意一天的记录内容，方便用户随时翻阅过去的心情足迹；

- 支持主题换肤（四叶草、樱花、天空、牛皮纸等主题），满足用户的个性化审美需求；

- 采用温柔提醒的方式培养用户的记录习惯，而非强硬的打卡机制。

本产品借鉴点：低门槛的文字/图片/标签输入方式；多视图回顾体验；主题换肤玩法。

### 3.2 Emoke（解压情绪记录日记）

- 核心创新是"情绪纸卷"机制：用户记录心情后可点燃纸卷，纸卷随物理动画慢慢卷曲、燃烧成灰，从而达到情绪舒缓的解压效果；

- 交互设计具有完整的仪式感：长按点燃 → 火苗蔓延 → 纸卷卷曲变黑，是一套精心设计的动画交互，而非简单的"删除确认"操作。

本产品借鉴点："点燃纸卷"的仪式感释放交互，作为负向情绪记录的处理方式核心参考。

### 3.3 本产品的差异化创新

在吸收上述两款产品长处的基础上，本产品最大的差异化创新在于引入"花园养成"机制，将"记录开心事"与"记录不开心事"两条行为路径统一收束到同一个花园生态系统中：开心事种下的种子会持续生长为花朵，不开心事燃烧后的灰烬会转化为花园养分反哺花朵生长。这种"正负情绪协同滋养同一片花园"的闭环机制，是当前竞品均未覆盖的空白点，也是本产品建立长期用户粘性与情感联结的核心壁垒。

### 3.4 竞品对比一览

| 维度 | Clovery 小幸运 | Emoke | 本产品（心情花园） |
| --- | --- | --- | --- |
| 记录门槛 | 极低（文字/图片/标签） | 中等（需完整书写纸卷内容） | 低（文字+图片+标签，双向记录） |
| 正向反馈机制 | 多视图回顾 | 无强化正向反馈 | 种子入土+花朵持续生长（核心创新） |
| 负向情绪处理 | 无专门机制 | 点燃纸卷仪式感释放 | 点燃纸卷+灰烬反哺花园（升级创新） |
| 养成/收集玩法 | 无 | 无 | 花之图鉴、进化花种、季节限定花 |
| 个性化主题 | 支持换肤 | 不明确 | 支持花园主题换肤 |

## 4. 目标用户与用户画像

- 有记录心情/情绪日记习惯，或希望培养该习惯的用户，尤其是 18-35 岁年轻女性用户；

- 喜欢治愈系、可爱系、养成类小工具的用户，对标"旅行青蛙""动物森友会"式的轻养成用户群体。

## 5. 用户故事/核心场景（User Story）

- 作为一名情绪细腻的年轻用户，我想要用最简单的方式（几个字+一张照片）记录下今天让我感到"谢谢，真好呀"的小事，以便我不需要花费很多时间和精力就能坚持记录习惯。

- 作为一名刚经历不愉快事情的用户，我想要把这件事写下来并"烧掉"释放，以便我能获得情绪上的舒缓，同时不必担心这段负面记录会被自己反复翻看而二次伤害。

- 作为一名喜欢养成类玩法的用户，我想要看到自己记录的开心事变成花园里真实生长的花朵，以便我能获得持续的成就感和陪伴感，愿意每天回来看看花园的样子。

- 作为一名希望保持记录习惯的用户，我想要收到温柔而不打扰的提醒，以便我能在合适的时间被轻轻唤起记录的念头，而不会产生被催促的压力感。

- 作为一名重视审美体验的用户，我想要为我的花园更换不同的主题风格（如樱花谷、薰衣草坡），以便花园的样子能符合我当下的心情或季节氛围。

## 7. 核心功能需求详述

本章重点详述产品最核心的三套机制：开心事记录→种花、不开心事记录→点燃纸卷→灰烬化肥料、花园养分系统。三者共同构成本产品的差异化壁垒，是评审重点关注章节。

### 7.1 开心事记录 → 种花机制

功能目标：让用户的每一次正向记录都获得可视化、持续性的情感回报，而非一次性的打卡反馈。

#### 7.1.1 输入流程

- 步骤1 用户在花园首页点击"种下开心事"主入口按钮，进入记录页面；

- 步骤2 支持文字输入（描述这件开心的事）+图片输入（相册选择/拍照，支持多图）；

- 步骤3 选择一个心情标签，标签与花种一一对应，示例：感恩🌻（向日葵）、惊喜🌷（郁金香）、陪伴💜（薰衣草）、成就🌾（麦穗）、美食🌸（樱花）、平静🍀（幸运草）等；

- 步骤4 日期时间可编辑（支持补记过去某天的开心事）；

- 步骤5 点击保存，触发种子落地反馈动画。

#### 7.1.2 种子落地反馈

- 保存后播放"种子入土"动画：种子从记录卡片飞入花园土壤，落地生根；

- 同步提示该花种当前的收集进度，例如"向日葵第7颗种子，再种3颗会长出第一朵花"，强化用户对"持续记录=持续收获"的心理预期；

- 花园中的花并非静态统计数字，而是随真实时间流逝自然生长的活地图：种子→发芽→抽叶→开花，用户下次打开 App 时能看到花朵比上次"又长大了一点"，形成持续的期待感和回访动力。

#### 7.1.3 进阶收集玩法

- 同类标签记录数量攒够阈值后，可解锁"进化花种"/稀有花变体，花朵形态、颜色更加丰富绚丽；

- 部分花种为季节限定（如樱花仅限每年3-4月可种），呼应真实季节变化，增强产品的时令感与新鲜感；

- 连续记录天数达到特定阈值（如连续21天）可解锁隐藏款花种，作为对长期坚持用户的专属奖励。

### 7.2 不开心事记录 → 点燃纸卷 → 灰烬化肥料机制

功能目标：为负向情绪提供一个具有仪式感的、安全的释放出口，同时避免负面记录被反复翻看造成二次伤害，并让释放行为本身产生正向价值（反哺花园）。

#### 7.2.1 输入流程

- 步骤1 用户在花园首页点击"点燃纸卷"主入口按钮，进入情绪纸卷记录页面；

- 步骤2 将不开心的事写进纸卷，支持文字+图片输入；纸卷 UI 采用做旧纹理造型，视觉上区别于开心事记录卡片，强化"待释放"的心理暗示；

- 步骤3 写完后进入"点燃引信"环节。

#### 7.2.2 点燃与燃烧动画

- 长按"点燃引信"按钮，出现长按进度条，模拟划火柴的仪式感；进度条上升过程中若松手，则中断点燃，用户可重新继续编辑纸卷内容；

- 长按满进度后自动播放燃烧动画：火苗从纸卷一端"吃"向另一端，纸卷逐帧卷曲、变黑、缩短，直至完全化为灰烬，整个过程配合动效与轻音效，营造沉浸式的释放仪式感；

- 燃烧完成后，灰烬以飘散动画的形式飘入花园土壤——这是灰烬唯一的归宿，不设置"随风飘散消失"等其他分支选项，保持机制单一纯粹，避免用户在释放这一关键情绪节点上产生决策负担。

#### 7.2.3 灰烬转化与隐私保护

- 灰烬飘入土壤后，将转化为花园养分值，养分值增加会让花园里的花长得更快更艳；

- 该记录在时光轴中仅保留一个抽象的"已转化为养分"封条式提示（不显示原文字/图片内容），原始记录内容不可再次查看、不可恢复，从产品机制层面保护用户不被负面记录二次伤害；

- 此机制传达的核心价值观：没有一种情绪是被浪费的，不开心的事最终也能反哺美好的事物生长。

### 7.3 花园养分系统

- 养分值由两个来源共同驱动，构成完整闭环：种花的正向记录（种子入土即增加基础养分）+烧灰的负向转化（灰烬飘入土壤增加额外养分）；

- 养分值直接影响花园整体的生长速度与繁茂程度：养分值越高，花朵生长周期越短、花朵形态越饱满艳丽；

- 养分值在花园首页以进度条形式常驻展示，让用户直观感受到"每一次记录（无论开心与否）都在滋养这片花园"，从而对正向和负向记录行为都产生持续激励。

### 7.4 机制闭环示意

开心事记录 → 种子入土 → 花朵生长（正向路径）与 不开心事记录 → 点燃纸卷 → 灰烬入土 → 转化养分 → 反哺花朵生长（负向转化路径），两条路径在"花园养分池"这一节点汇合，最终共同作用于同一片花园的生长表现，形成"无论情绪好坏，都在为花园做贡献"的完整正循环闭环，这是本产品区别于其他情绪记录类 App 的核心机制护城河。

## 9. 关键用户流程图

以下用文字描述"记开心事"与"记不开心事"两条主流程的步骤序列，供开发与设计团队梳理交互细节时参考。

### 9.1 记开心事 主流程

- 步骤1 用户打开 App，进入花园首页

- 步骤2 点击"种下开心事"按钮

- 步骤3 进入记录页面，输入文字描述（可选配图片，支持多图）

- 步骤4 选择心情标签（对应花种，如感恩🌻/惊喜🌷/陪伴💜等）

- 步骤5 确认或编辑日期时间

- 步骤6 点击保存

- 步骤7 播放种子落地动画（种子飞入花园土壤）

- 步骤8 展示该花种当前收集进度提示（如"向日葵第7颗种子，再种3颗会长出第一朵花"）

- 步骤9 返回花园首页，花园全景与养分值进度条同步更新

- 步骤10 记录同步写入时光轴对应日期

### 9.2 记不开心事 主流程

- 步骤1 用户打开 App，进入花园首页

- 步骤2 点击"点燃纸卷"按钮

- 步骤3 进入情绪纸卷记录页面，输入文字描述（可选配图片）

- 步骤4 点击"点燃引信"按钮并长按

- 步骤5 长按进度条上升，模拟划火柴的仪式感（若中途松手则中断，可继续编辑内容）

- 步骤6 长按满进度后自动触发燃烧动画：火苗从一端"吃"向另一端，纸卷逐帧卷曲、变黑、缩短

- 步骤7 纸卷完全化为灰烬

- 步骤8 灰烬飘散动画：灰烬飘入花园土壤（唯一归宿，无其他分支选项）

- 步骤9 花园养分值增加，花园生长速度/繁茂程度同步提升

- 步骤10 该记录仅在时光轴留存"已转化为养分"的抽象封条提示，原始内容不可再次查看

## 10. 非功能需求

| 方向 | 需求说明 |
| --- | --- |
| 平台 | 首发平台为 iOS，后续视用户增长与市场反馈考虑拓展 Android 平台 |
| 数据安全与隐私 | 情绪记录文字、图片等属于用户敏感数据，需考虑本地存储加密方案，云同步功能需明确用户授权机制与隐私保护措施，灰烬转化后的原始记录需做到物理层面不可恢复，从技术上落实"不可再次查看"的产品承诺 |
| 性能 | 花园生长动画、点燃燃烧动画等核心动效需保证流畅运行，同时控制低电量与低内存消耗，避免因动画资源占用过高影响用户日常使用体验 |
| 无障碍 | 支持文字大小可调节，色彩对比度设计需照顾色弱/色盲用户的可读性与可辨识性需求 |
| 稳定性 | 记录数据需具备本地持久化与异常恢复能力，避免因崩溃、断网等异常情况导致用户记录内容丢失 |

## 11. 视觉与交互风格要求

### 11.1 色系

| 色彩 | 应用场景 |
| --- | --- |
| 奶油白 | 整体背景基底色，营造干净、柔和、治愈的视觉基调 |
| 暖橘黄 | 开心事记录相关元素、花朵主色调，传达温暖、积极的情绪联想 |
| 雾雾灰粉 | 不开心事记录相关元素、纸卷主色调，传达柔和、安全的释放氛围（区别于常见的沉重灰暗色） |
| 鼠尾草绿 | 点缀色，用于叶片、花园背景细节，平衡整体色彩的活力与自然感 |

### 11.2 字体

全局采用圆润、亲和力强的字体（如系统默认圆体或类似风格字体），标题字号适度加大以突出温暖治愈的视觉基调，正文字号需满足无障碍可调节需求，避免使用过于锐利、冷硬的字体风格。

### 11.3 插画与交互风格

- 整体界面采用圆角卡片作为内容承载容器，避免直角、锐利边缘带来的紧张感；

- 花园、花朵、纸卷、种子等核心元素均采用手绘插画风格，弱化写实感，强化童话感与温暖感；

- 核心交互动效（种子入土、花朵生长、点燃燃烧）需具备充分的仪式感与情感反馈强度，让用户感知到"每一次操作都有意义"，而非简单的功能性交互；

- 整体交互节奏偏慢、偏柔和，避免过强的游戏化竞争感，保持情绪记录产品应有的舒缓基调。

## 12. 待定事项/开放问题

以下问题需在后续产品评审与设计细化阶段进一步明确：

- 花种与心情标签对照表的完整细节：需明确全部心情标签清单及对应花种、花色、稀有度分级标准；

- 花的生长是否支持用户主动加速交互（如每日浇水/晒太阳等），若支持，需明确该类交互是否会削弱"真实时间流逝自然生长"这一核心心智，需评估其对产品差异化定位的影响；

- 最终产品名称与视觉识别系统（VI）的确定："谢谢日记"与"心情花园"两个命名方向的最终取舍；

- 最终实现载体的选择：原生 iOS 开发 / 跨平台框架（如 Flutter、React Native）等技术方案待评估；

- 云同步功能的具体实现方式与是否需要账号体系（如是否支持游客模式、是否需要多端同步）；

- 隐藏款花种与季节限定花的具体解锁规则、数量规模及后续内容更新节奏；

- 商业化模式的探索方向（如主题皮肤付费解锁、稀有花种内购等），需评估其与产品"治愈系"调性的兼容性。
